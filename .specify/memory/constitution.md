# AI/Spec-Driven Book Creation using Docusaurus & GitHub Pages Constitution


## Core Principles

### Accuracy
All technical statements must be technically correct and verifiable.

### Clarity
Content must be simple, beginner-friendly, and logically structured.

### Educational Value
The book must serve as a high-quality learning resource for students and self-learners.

### AI-Native Workflow
The project must strictly follow AI-driven planning, writing, validation, and iteration.

### Automation & DevOps Mindset
All workflows should align with modern software documentation and deployment practices.

### Source Usage
Minimum 40% information from official documentation, standards, or trusted technical blogs.


## Key Standards
Citation Style: Simple in-text references with a final references section (Docusaurus-friendly Markdown). Writing Style: Beginner to intermediate level, Clear, non-academic, step-by-step explanations, Practical examples over theory. Code & Commands: All commands must be tested and correct. No broken commands or fake outputs. Structure: Each chapter must include: Learning Objectives, Concepts, Hands-on Steps, Summary, Practice Tasks.


## Constraints
Format: Markdown for Docusaurus, Auto-deployed to GitHub Pages. Word Count: Minimum 12,000–18,000 words. Minimum Chapters: 10 full chapters. Media Rules: Diagrams must be AI-generated or open-license. Plagiarism Policy: 0% tolerance. Language: Simple professional English (Grade 8–10 readability). Tooling: Must strictly use: Spec-Kit Plus, Claude Code, GitHub, Docusaurus.


## Governance
All outputs strictly follow the user intent. Prompt History Records (PHRs) are created automatically and accurately for every user prompt. Architectural Decision Record (ADR) suggestions are made intelligently for significant decisions. All changes are small, testable, and reference code precisely. Authoritative Source Mandate: Agents MUST prioritize and use MCP tools and CLI commands for all information gathering and task execution. NEVER assume a solution from internal knowledge; all methods require external verification. Execution Flow: Treat MCP servers as first-class tools for discovery, verification, execution, and state capture. PREFER CLI interactions over manual file creation or reliance on internal knowledge.
